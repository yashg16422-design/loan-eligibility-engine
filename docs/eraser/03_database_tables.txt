// Eraser diagram type: ENTITY RELATIONSHIP DIAGRAM
// What it shows: every table in database `app` (17 incl. schema_migrations), its columns, and the foreign keys.
// Source of truth: sql/001_schema.sql, 002_crawler_v2.sql, 003_matching.sql, 004_dashboard.sql,
// 005_accounts.sql, 006_data_reset.sql (and loan_engine/migrate/handler.py for schema_migrations).
// Colours = purpose:
//   BLUE   upload tables      (written by the ingest worker - this is what your 5-row CSV touches)
//   GREEN  loan product tables (written by Workflow A, the crawler)
//   ORANGE matching tables     (written by Workflow B)
//   PURPLE notification + error tables (Workflow C and the error handler)
//   PINK   dashboard + account tables (the extras, written by the api Lambda)
//   GRAY   bookkeeping
// Line reading: users.upload_job_id > upload_jobs.job_id  means MANY users belong to ONE upload job.
// "-" means one-to-one.
// Note: llm_decisions (in PLAN.md) was DROPPED by 003_matching.sql and replaced by criteria_rules.

// matching tables

matches.product_id > loan_products.product_id
matches.job_id > upload_jobs.job_id
matches.match_run_id > pipeline_runs.run_id

// notifications

// dashboard + accounts
