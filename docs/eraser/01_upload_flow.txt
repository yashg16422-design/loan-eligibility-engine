// =====================================================================
// HAPPY PATH (numbered)
// =====================================================================
submitHandler > createTicket: 0 user clicks upload
createTicket > apiGateway: 1 POST /uploads body filename five.csv
apiGateway > handlerFn: 2 event version 2.0 routeKey POST /uploads
handlerFn > createUpload: 3 Mangum hands the request to FastAPI
createUpload > postPolicy: 4 get the pass rules
createUpload > createJob: 5 write the note FIRST
createJob > tUploadJobs: 6 INSERT status AWAITING_UPLOAD attempts 0
createUpload > presignPost: 7 sign the pass
createUpload > apiGateway: 8 returns dict, Mangum makes statusCode 201
apiGateway > createTicket: 9 HTTP 201 JSON job_id + upload url + fields + delete_key, cache-control no-store
createTicket > uploadToS3: 10 hands over the pass
uploadToS3 > s3Object: 11 POST multipart/form-data, signed fields first, file LAST, Origin header added by browser
s3Object --> uploadToS3: 12 HTTP 204 success (or 403 if the pass is wrong, nothing stored)
s3Object > sqsQueue: 13 ObjectCreated event, only prefix raw/ and suffix .csv
sqsQueue > ingestHandler: 14 wakes the worker, ApproximateReceiveCount 1
ingestHandler > parseSqs: 15 open the message
parseSqs > jobIdFromKey: 16 validate the S3 key
jobIdFromKey > credsFn: 17 key ok, now log in
credsFn > secretsMgr: 18 read DB password via VPC endpoint
credsFn > connectDb: 19 password in hand
connectDb > bumpAttempts: 20 connected
bumpAttempts > tUploadJobs: 21 attempts + 1 (autocommit, survives rollback)
bumpAttempts > claimJob: 22 next
claimJob > tUploadJobs: 23 SELECT FOR UPDATE SKIP LOCKED then status PROCESSING (inside the transaction)
claimJob > iterLines: 24 claimed, now read the file
iterLines > s3Object: 25 get_object streamed line by line, BOM stripped
iterLines > validateCsv: 26 lines flow in
validateCsv > loadUsers: 27 4 valid rows (Aarav, Meera, Kabir, Ananya)
loadUsers > tUsers: 28 COPY staging_users then upsert, 4 inserted
loadUsers > saveRejects: 29 1 rejected row
saveRejects > tRejects: 30 COPY row 6 reason credit_score_out_of_range
saveRejects > completeJob: 31 almost done
completeJob > tUploadJobs: 32 status COMPLETED + counts, COMMIT
completeJob > notifier: 33 only after COMMIT
notifier > webhookB: 34 POST job_id with X-Webhook-Secret, private network, port 5678 open to Lambda SG only
webhookB > workflowB: 35 Workflow B takes over
workflowB > tLater: 36 writes pipeline_runs, classes, pairs, matches
workflowB > workflowC: 37 run finished
workflowC > tLater: 38 writes notifications

// =====================================================================
// POLLING PATH (the browser keeps asking)
// =====================================================================
pollRender > apiGateway: P1 GET /uploads/job_id every 2 s until finished (stops after 20 min)
apiGateway > getUpload: P2 route GET /uploads/job_id
getUpload > getJobProgress: P3 load progress
getJobProgress > tUploadJobs: P4 read the note
getJobProgress > tRejects: P4 read first 20 rejects
getJobProgress > tLater: P4 read latest match run and notification counts
getJobProgress > deriveStatus: P5 add computed states
getUpload > pollRender: P6 JSON job + rejects + match_run + notifications, render() draws the steps

// =====================================================================
// FAILURE AND RETRY PATHS (dotted)
// =====================================================================
claimJob -- ingestHandler: F1 no row to claim = duplicate or already done, exit quietly
validateCsv -- failJob: F2 missing column or not UTF-8, FAILED at once, no retry
ingestHandler -- sqsQueue: F3 random error, re-raise, SQS redelivers after 720 s, up to 3 receives
ingestHandler -- failJob: F4 on the 3rd try mark FAILED in a separate transaction, message consumed
failJob -- tUploadJobs: F4 status FAILED + error text
sqsQueue -- sqsDlq: F5 Lambda killed (timeout or out of memory) 3 times, message moves to the dead-letter queue
sqsDlq -- alarmFlow: F6 alarm emails you
notifier -- sweeper: F7 n8n down, webhook gave up quietly
sweeper -- tUploadJobs: F8 within 10 min finds COMPLETED jobs with match_status empty and picks them up
sweeper -- workflowB: F9 starts matching
s3Object -- tUploadJobs: F10 pass invalid or file never uploaded, note stays AWAITING_UPLOAD, shown as EXPIRED after 15 min
